# BWS Engineering Sdn Bhd: website

Corporate website for **BWS Engineering Sdn Bhd**, a Bumiputera oil & gas construction and maintenance contractor based in Miri and Bintulu, Sarawak. It replaces the old Wix site at www.bwsengineeringsb.com.

It is a plain static site: HTML, one CSS file and one small JavaScript file, plus an optional PHP form handler (`contact.php`). There is no framework and no build step to deploy: upload the **`site/`** folder to any static host. The pages themselves are generated by `tools/generate_site.py` (see "Tools").

## BWS Portal (job applications and HR admin)
The **`portal/`** folder is a separate Laravel app for **vacancies, online job applications with CV upload, and the HR admin panel**. It runs on a PHP host (cPanel) at `portal.bwsengineeringsb.com`; see **`portal/README.md`** for setup and day-to-day use.
- The Careers page asks the portal for open vacancies. If it answers, the page shows them with an *Apply online* form; if not (portal not deployed yet, or down), that section stays hidden and the "Send your CV" email option works as before.
- The portal address is `PORTAL` at the top of `tools/generate_site.py`. If it changes, update it there, in the `connect-src` part of the Content-Security-Policy in `vercel.json` and `site/.htaccess`, and in `PORTAL_SITE_ORIGINS` in the portal's `.env` if the website address changes.

## Deploy

| Host | How |
|---|---|
| **Netlify** | Drag the `site/` folder onto app.netlify.com/drop, or connect this repo and set the *publish directory* to `site`. |
| **Vercel** | Import the repo and set the *Root Directory* to `site`. Framework preset: *Other*. |
| **cPanel / Apache** | Upload the **contents** of `site/` into `public_html/`. The included `.htaccess` turns on compression, caching and the 404 page, and `contact.php` delivers enquiries by email (see "Contact form"). |

After going live on the real domain, submit `https://www.bwsengineeringsb.com/sitemap.xml` in Google Search Console.
If the domain changes, search and replace `https://www.bwsengineeringsb.com` across `site/` (it appears in canonical links, Open Graph tags, JSON-LD, `sitemap.xml` and `robots.txt`).

Every page repeats the same header and footer. If you change a phone number, a menu item or similar, change it in **all 9 HTML files** (a find-and-replace across `site/*.html` does it in one go).

## Common edits

### Swap or add photos
1. Export the photo as WebP (or JPG) at **800 px wide** (and optionally 480 and 1600 px wide). Use free tools like squoosh.app, or `cwebp -q 75 in.jpg -o out.webp`.
2. Put it in `site/assets/img/`, e.g. `civil-jetty-800.webp`.
3. In the HTML, change the `src` (and `srcset` if present), the `width`/`height` (the real pixel size of the 800 px file) and the **`alt` text** (describe what's in the photo).

Gallery photos (`projects.html`) are `<li data-cat="...">` items. Copy an existing one, change the file names, `data-full` (big version shown in the lightbox), `data-title` and `alt`. Categories: `plant`, `mech`, `civil`, `ei`, `hse`. The counts on the filter buttons are worked out by the generator from the `GALLERY` list in `tools/generate_site.py`; if you hand-edit the HTML instead, update them yourself.

**Placeholders** are grey striped boxes with a `<!-- PLACEHOLDER PHOTO … -->` comment above them. Replace the whole `<div class="ph">…</div>` with an `<img>`. For gallery items, copy a real gallery `<li>` instead.

### Swap the logo
Replace `site/assets/logo/logo.svg` and `logo-white.svg` (keep the file names). If the new logo has a different shape, update the `width`/`height` on the `<img>` tags in the header and footer.

### Privacy Notice
`privacy.html` (and `ms/privacy.html`) explains what personal data the forms collect, why, who sees it, how long it is kept, and how to ask for access, correction or deletion, as Malaysia's Personal Data Protection Act 2010 expects. The text is in `PRIVACY_SECTIONS` in `tools/generate_site.py`.
- ⚠️ **BWS should have it reviewed** (by its company secretary or a lawyer) before launch, and keep it true: for example, if CVs are kept longer than 12 months, change both the notice and `PORTAL_RETENTION_MONTHS`.
- When the notice changes, update `PRIVACY_VERSION` there and `PORTAL_PRIVACY_VERSION` in the portal's `.env`, so each application records which version the applicant agreed to.
- **When the BWS Portal goes live,** update two lines in `PRIVACY_SECTIONS` to match: applications and CVs are then deleted *automatically* after 12 months, and CVs are stored in the portal where only logged-in staff can open them. Until then the notice describes the email process (CVs kept up to 12 months in BWS's own email and records), so BWS's recruitment team must actually delete CVs older than 12 months.

### Contact form
The form is on `contact.html` (search for `CONTACT FORM`). It sends in the background and shows a thank-you message, trying three routes in turn:
1. **The BWS Portal** (`/api/enquiries`): saved in the portal's **Enquiries** list (with status and notes for follow-up) and emailed to bws@bwsengineeringsb.com.
2. **`contact.php`**, if the portal doesn't answer: emailed only (details below).
3. **The visitor's email app**, pre-filled, if neither answers.

About `contact.php`:
- **cPanel / any host with PHP:** works as soon as it is uploaded. Enquiries are emailed to **bws@bwsengineeringsb.com** with *Reply-To* set to the visitor, so replying answers them directly. Settings are at the top of `site/contact.php`:
  - `TO_EMAIL`: where enquiries go. `CC_EMAIL`: an optional second inbox.
  - `FROM_EMAIL`: must be an address on the website's own domain (it doesn't need to be a real mailbox), or Gmail and Outlook may file enquiries as spam.
  - `MAX_PER_HOUR`: submissions allowed per visitor per hour (default 5).
  - Spam protection: a hidden "honeypot" field, plus the hourly limit. Name and subject are cleaned so the form can't be used to send email to anyone else.
  - Send yourself a test enquiry after uploading. If nothing arrives, check the spam folder, then ask the host whether PHP `mail()` is enabled.
- **Hosts without PHP (Vercel, Netlify, GitHub Pages):** *Send enquiry* opens the visitor's email app with the enquiry pre-filled instead. Nothing needs setting up, and `.vercelignore` keeps `contact.php` off Vercel.
- **Formspree instead:** create a form at **formspree.io** and set the form's `action` to `https://formspree.io/f/<your form ID>` in `contact()` in `tools/generate_site.py`.
- Netlify users can instead add `data-netlify="true"` and `name="enquiry"` to the `<form>` and remove the `action`.

### Security headers
`vercel.json` sets a Content-Security-Policy, HSTS, X-Frame-Options, Referrer-Policy and Permissions-Policy, plus caching rules (`site/.htaccess` does the same on Apache/cPanel). If you add a new external service (analytics, a chat widget, another embed), add its domain to the CSP or the browser will block it.

## Bahasa Melayu version
The Malay site lives in `site/ms/` (e.g. `/ms/about.html`). The **EN | BM** button in the header switches between the same page in each language. Both versions carry `hreflang` links, and `sitemap.xml` lists both.
- Pages are **generated automatically** from the English ones when you run `python3 tools/generate_site.py` (via `tools/build_ms.py`).
- Translations are in `tools/ms_strings.py`, keyed by the exact English text. If you change English copy, add or update its Malay line too, or that text stays in English on the BM page. Each build writes the list of strings kept in English to `tools/ms_untranslated.txt`, so `git diff` shows any new English text that still needs a Malay line.
- **Kept in English on purpose:** project titles, client and agency names, certificate scopes, and codes, as they appear in the official records.
- ⚠️ **Have a native speaker at BWS proofread the Malay before launch.** It's written in formal business Bahasa Malaysia, but not yet reviewed by a person.

## Accessibility & performance notes
- WCAG AA contrast throughout, a skip link, visible focus outlines, a keyboard-operable menu (Esc closes, focus is trapped while open) and lightbox (← → Esc). Labelled form fields with error messages.
- Animations (reveal-on-scroll, counters, client marquee) switch off when the visitor's device asks for reduced motion.
- Images are WebP with fixed `width`/`height` (no layout jumping), lazy-loaded below the fold, and use `srcset` so phones get smaller files.
- Lighthouse (mobile, local test server): **Performance 98–99, Accessibility 100, Best Practices 100, SEO 100**, layout shift 0, blocking time 0 ms.
- Scrolling is kept cheap: no backdrop blur or blend modes, only opacity/transform animations, and a throttled scroll handler. It measured a steady 60 fps.

## Tools (optional)
- `tools/generate_site.py` is the script that generated the HTML pages from shared header/footer templates. Use it **or** hand-edit the HTML, not both: running it overwrites every page. Run with `python3 tools/generate_site.py`.
- `tools/build_css.py` joins `src/css/*.css` into `site/assets/css/styles.css`. The generator runs it first; run it on its own after a CSS-only change.
- `tools/check_site.py` checks every page for broken links and image paths, `#section` links to missing ids, images without alt text and duplicate ids. Run it after any edit: `python3 tools/check_site.py`.
- **GitHub check** (`.github/workflows/check-site.yml`): on every push it rebuilds the pages, warns if the committed HTML differs from what the generator produces, runs `check_site.py` and syntax-checks `contact.php`. A second job runs the portal's code-style check and tests.
- `tools/make_logo.py` rebuilds the logo SVGs. It needs `pip install fonttools` and the Noto Serif variable font (`NotoSerif[wdth,wght].ttf` from github.com/google/fonts, saved as `fonts/NotoSerif.ttf`).
