# Group C: project map and "Since 2002" timeline — design

Date: 2026-10-22. Approved in chat.

Out of scope:
- Case studies and certificate cards already exist on main.
- The hero video is deferred until BWS supplies footage or high-resolution photos.

All pages on main are generated by `tools/generate_site.py`, and CI fails if the committed HTML differs from its output. Change only the generator, `src/css/` and `tools/`, then regenerate.

## 1. Project map (projects.html, directly above "Key projects")

**Data**
- Group the 4th field (location) of every `PROJECTS` entry into places.
- Normalise the strings: "Bintulu, Sarawak" becomes Bintulu. A string naming several places, like "Bario, Mulu & Telang Usan, Sarawak", counts once for each named place.
- Keep the mapping explicit and reviewable in a `PLACES` table in a new `tools/make_project_map.py`:
  - place key → display name EN/BM, lat, lon
  - the location strings that map to it
- Fail loudly if a `PROJECTS` location doesn't map to any place.

**Geodata, cached in `tools/data/`, with a `--fetch` option to refresh**
- **Coastline:** Natural Earth 1:10m land, public domain. Clip it to Borneo north of about 0.8° N, covering Sarawak, Brunei, Sabah and Labuan, then simplify it. If any project is in Peninsular Malaysia, add a small inset frame for it, labelled "PENINSULAR MALAYSIA".
- **Place coordinates:** OpenStreetMap Nominatim, 1 request per second, with a User-Agent. Cache the results.
- **Credit:** "© OpenStreetMap contributors · Natural Earth" in the drawing.

**Drawing**
- Inline SVG, in the blueprint style of `tools/make_locations.py` and `make_illustrations.py`: ink sheet, sky grid, cyan coast, north arrow, true-scale bar, and a title block "DWG BWS-PRJ-01 · PROJECT LOCATIONS · REV A".
- **Pins:**
  - Each place is a circle whose area is proportional to its project count, labelled with the place name and count, e.g. "BINTULU · 35".
  - Miri (HQ) and Bintulu (yard) get a distinct base marker, labelled "BWS BASE".
  - Labels must not overlap. Use per-place label offsets in `PLACES` where needed.
- **Accessibility:** each pin is wrapped in an `<a>`, or carries a `button` role, with `aria-label` "Bintulu: 35 projects — show in list" and a visible focus ring. The SVG has a `<title>` and `<desc>`. A visually hidden list under the map gives each place and its count, as a text alternative.
- **Behaviour (main.js):** activating a pin puts the place name into the existing Key-projects search box, runs the existing filter (dispatch an `input` event) and scrolls the list into view. Keep this a few lines, reusing the existing code. With JavaScript off, the map still shows names and counts.
- **BM:** pin aria-labels and the visible labels go through `ms_strings.py` / `build_ms.py`. Place names stay as proper nouns. "PROJECT LOCATIONS" becomes "LOKASI PROJEK", and "projects" becomes "projek".
- **Size:** aim for 30–60 KB of uncompressed SVG.

Use only facts already stated on the site:

- **Data:** a `TIMELINE` list in `generate_site.py`, with each row's source noted in a comment, plus BM strings in `ms_strings.py`.

- **Layout:** horizontal scroll-snap rail on wide screens, vertical line on phones. It uses blueprint styling and the three-panel marker, and respects reduced motion (no animation needed).
- **README:** a needs-from-BWS row asking BWS to confirm the timeline.
